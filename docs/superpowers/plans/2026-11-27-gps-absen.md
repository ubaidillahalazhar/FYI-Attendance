# GPS Absen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clock In/Out uses the phone's real GPS + accuracy; the server rejects poor accuracy and out-of-radius, and records distance/accuracy for HR.

**Architecture:** Extend the existing `GeofenceService`/`AttendanceController` checks (server stays the only judge). `/me` hands the office config to the frontend so `.env` backend is the single source. Frontend fetches a fresh position on each tap; the simulator survives only in mock mode.

**Tech Stack:** Laravel 12 + Sanctum, PHPUnit; React 18 + Vite, browser Geolocation API.

**Spec:** `docs/superpowers/specs/2026-11-27-gps-absen-design.md`

## Global Constraints

- `accuracy` required on clock-in and clock-out: `numeric`, `min:0`.
- Max accuracy from `GEOFENCE_MAX_ACCURACY_METERS`, default `100`; accuracy `<=` max passes.
- Check order: validation → accuracy → radius → existing business checks.
- Accuracy-reject message (422, exact): `Akurasi GPS ±{acc} m terlalu rendah (maks {max} m). Coba dekat jendela atau area terbuka, lalu ulangi.` where `{acc}` = rounded integer.
- Existing column `distance_in_meters` already holds clock-in distance — reuse it; add only `clock_in_accuracy_m`, `clock_out_distance_m`, `clock_out_accuracy_m` (unsigned int, nullable). (Spec said 4 columns; 3 suffice.)
- Geolocation options: `{ enableHighAccuracy: true, maximumAge: 0, timeout: 15000 }`.
- Mock mode (`VITE_USE_MOCK=true`) keeps the simulator and office coords; no backend calls.
- No new dependencies.

## Review Focus

1. GPS permission denied → toast with the browser's message, no API call, buttons usable again. (Task 2 manual check)
2. Double tap while GPS is resolving → only one request (buttons disabled while `gpsLoading`). (Task 2 manual check)
3. Accuracy exactly at the max (100) → accepted. (Task 1 test)
4. Far location with great accuracy → rejected by radius, not by accuracy. (Task 1 test)
5. Old client without `accuracy` → 422 validation error, nothing saved. (Task 1 test)
