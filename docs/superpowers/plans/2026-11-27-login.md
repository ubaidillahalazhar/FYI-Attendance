# Login (HR & Peserta) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Email+password login with roles `hr` / `peserta`; server takes the peserta's identity from the token and locks admin endpoints to HR.

**Architecture:** Laravel 11 + Sanctum personal access tokens. `users` gets `role` + `employee_id`. Role checks are two Gates (`hr`, `peserta`) used as `can:` route middleware — no custom middleware classes. React stores the token in `localStorage` and picks the view from `user.role`.

**Tech Stack:** PHP 8.3, Laravel 11, Sanctum 4, PostgreSQL 16, PHPUnit (Laravel feature tests), React 18 + Vite 5.

**Spec:** `docs/superpowers/specs/2026-11-27-login-design.md`

## Global Constraints

- Roles exactly `hr` and `peserta`; default `peserta`.
- Login endpoint `POST /api/login` with `throttle:5,1`.
- `employee_id` from request bodies is ignored for peserta endpoints.
- Mock mode (`VITE_USE_MOCK=true`) keeps working without login.
- `postcss` `^8.4.47` (not `^10.4.47`).
- Dev DB `geoattend_hr`, test DB `geoattend_hr_test`, user `postgres` / `postgres_password`, port 5432.

## Review Focus

1. Peserta sends another person's `employee_id` in the body → record is saved under their own employee. (Task 3 test)
2. HR account (no `employee_id`) calls clock-in → 403, not a 500. (Task 3 test)
3. Login with `Budi.Santoso@Company.co.id` (different case) → succeeds; email is lowercased before lookup. (Task 2 test)
4. Peserta whose employee is `is_active = false` (PKL finished) → login rejected with 422. My call — spec is silent; prevents ex-participants from clocking in. (Task 2 test)
5. Sixth wrong password within a minute → 429. (Task 2 test)
